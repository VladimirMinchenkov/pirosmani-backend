## Зачем нужен Figma-макет

Telegram Mini App форкает UI из [`pirosmani-frontend`](../pirosmani-frontend), но с тремя
структурными изменениями, которые затрагивают компоновку всех экранов:

1. **Вместо `BottomNav`** (5 вкладок внизу) → навигация через header с Telegram `BackButton`
2. **Вместо кастомной CTA-кнопки** → нативная Telegram `MainButton` (фиксирована внизу WebView)
3. **Цвета из `WebApp.themeParams`** → адаптивная светлая/тёмная тема (вместо хардкод-пропа `isDark`)

Без макета разработчик (особенно слабая модель) соберёт эти 3 изменения непредсказуемо —
высота header'а, отступ от MainButton, контраст в тёмной теме могут «поплыть».
Макет даёт единый визуальный ориентир.

**Важно**: в Mini App **нет** phone-frame обёртки (Dynamic Island, статус-бар, скруглённые
углы телефона) — Telegram WebView сам занимает весь экран. Макет должен показывать
интерфейс на всю ширину фрейма (390×844 или пропорционально), без имитации корпуса телефона.

## Экран 1: MenuPage — меню (главный экран)

### Что переиспользуется из `pirosmani-frontend/src/pages/MenuPage.tsx`

| Компонент | Изменения |
|---|---|
| Логотип «Пиросмани» + статус кафе (открыто/закрыто) | Без изменений |
| Иконка корзины (badge с количеством) | Без изменений |
| Горизонтальный скролл категорий (Хинкали, Супы, …) | Без изменений |
| Горизонтальный скролл тегов (Острое, Вегетарианское, …) | Без изменений |
| Карточки блюд (изображение, название, цена, вес, кнопка +) | Без изменений |
| WelcomeBanner / RepeatOrderBanner / FrequentItems | Без изменений |
| DishDetailSheet (модалка деталей блюда) | Без изменений (вызывается так же) |

### Что меняется

1. **Header**:
   - Высота: ~56px (как стандартный header Telegram, с учётом safe-area).
   - Слева: **логотип-эмодзи + «Пиросмани»** (Fraunces, 22px, #D36135).
   - Справа: **иконка корзины с badge** (такая же, как сейчас).
   - `BackButton` на этом экране **не показывается** (это корневой экран).
   - Фон header'а = `bg_color` из `themeParams`.

2. **MainButton**:
   - Показывается **только когда корзина не пуста**.
   - Текст: `Корзина (3) на 45.90 BYN` — динамический, с количеством и суммой.
   - Цвет: `button_color` из `themeParams`.
   - Текст: `button_text_color`.
   - Расположение: прижата к низу WebView, поверх контента (не скроллится вместе со страницей).
   - Высота: стандартная Telegram (~50–56px).
   - При тапе → переход на `CartPage`.

3. **Отсутствует `BottomNav`** — нижние 62px освобождены. Контент (список блюд) скроллится до самого низа, а MainButton накладывается поверх.

4. **Цвета**:
   - Фон страницы = `bg_color` (светлая: #FDFBF7, тёмная: tg default).
   - Карточки блюд = `secondary_bg_color` (светлая: #EDE5D8, тёмная: tg default).
   - Текст = `text_color`.
   - Второстепенный текст = `hint_color`.
   - Акцент (цена, кнопка +, badge корзины) = `button_color` ИЛИ фирменный #D36135 (на усмотрение — провалидировать в макете, что оранжевый #D36135 не конфликтует с Telegram-темой).

### Состояния для макета

- [ ] **Базовое**: меню с блюдами, корзина пуста (MainButton скрыта).
- [ ] **С товарами в корзине**: корзина не пуста (badge и MainButton видны).
- [ ] **Тёмная тема** (переключить в Figma: bg_color ≈ #1A1A1A, text_color ≈ #F5EDE0).

## Экран 2: CartPage — корзина

### Что переиспользуется

| Компонент | Изменения |
|---|---|
| Заголовок «Корзина» + счётчик позиций | Без изменений |
| Список товаров (изображение, название, +/- количество, цена) | Без изменений |
| Подсказка «Минимальная сумма заказа» | Без изменений |
| Кнопка «Добавить ещё» (dashed) | Без изменений |
| Сумма заказа | Без изменений |
| Пустое состояние корзины | Без изменений |

### Что меняется

1. **Header**:
   - Слева: Telegram `BackButton` (стрелка влево) — возврат на `MenuPage`.
   - По центру или сразу за BackButton: «Корзина» (Fraunces, 22px).
   - Справа: ничего (или счётчик позиций, как сейчас в карточке-заголовке). **Решить в макете**: стоит ли дублировать счётчик в header'е или оставить только в карточке под header'ом.

2. **MainButton**:
   - Текст: `К оформлению` (когда сумма ≥ минимальной) ИЛИ `Минимум 30.00 BYN` (когда сумма меньше минимальной, кнопка disabled-стиля).
   - Disabled-стиль: приглушённые цвета (вместо `button_color` — `hint_color` с opacity).
   - При тапе (enabled) → переход на `CheckoutPage`.

3. **Отсутствует** кастомная CTA-секция (`padding: '10px 16px 96px'`) — заменена на MainButton. Контент корзины скроллится до низа, MainButton всегда видна поверх.

4. **Цвета**: те же CSS-переменные из `themeParams`.

### Состояния

- [ ] **Корзина с товарами, сумма ≥ минимума** (MainButton активна).
- [ ] **Корзина с товарами, сумма < минимума** (MainButton disabled).
- [ ] **Пустая корзина** (MainButton скрыта, только кнопка «Перейти в меню»).
- [ ] **Тёмная тема** (все 3 состояния выше).

## Экран 3: CheckoutPage — оформление заказа

Это самый сложный экран. Исходник: [`CheckoutPage.tsx`](../pirosmani-frontend/src/pages/CheckoutPage.tsx) (~1106 строк).

### Что переиспользуется

| Секция | Изменения |
|---|---|
| Переключатель «Доставка / Самовывоз» | Без изменений |
| Адрес доставки (выбор из сохранённых + кнопка «Добавить адрес») | Без изменений |
| AddressForm (модалка добавления адреса) | Без изменений |
| Комментарий к заказу (textarea) | Без изменений |
| Выбор времени (⚡ Как можно быстрее / 🗓 Запланировать) | Без изменений |
| Промокод | Без изменений |
| Бонусы (слайдер/переключатель) | Без изменений |
| Карточная форма (CardForm) | Без изменений |
| Итоговая сумма с расшифровкой скидок | Без изменений |

### Что меняется

1. **Header**:
   - Слева: `BackButton` → возврат на `CartPage`.
   - Заголовок: «Оформление заказа» (не «Корзина»).

2. **MainButton**:
   - Текст: `Подтвердить заказ · 45.90 BYN`.
   - Состояния:
     - **Активна** — все поля валидны (адрес выбран, карта заполнена).
     - **Disabled** — обязательные поля не заполнены ИЛИ идёт загрузка («Оформляем заказ…»).
     - **Скрыта** — когда открыта AddressForm (модалка перекрывает MainButton? В Telegram MainButton обычно остаётся видимой — **провалидировать в макете**).

3. **Отсутствует** кастомная CTA-секция (`padding: '10px 16px 96px'`) с кнопкой «Подтвердить заказ» и ошибкой `orderError`. Ошибку нужно показывать **над MainButton** (всплывающий блок, не перекрывающий кнопку) — или через Telegram `Popup`.

4. **Отступ снизу для скролла** — контент чекаута должен скроллиться так, чтобы последний элемент (итоговая сумма) был виден над MainButton. Рекомендуется `padding-bottom: 60px` у скролл-контейнера.

### Состояния

- [ ] **Доставка, всё заполнено** (MainButton активна).
- [ ] **Самовывоз** (адрес скрыт, MainButton активна).
- [ ] **Ошибка** (например, зона доставки не определена) — сообщение над MainButton.
- [ ] **Загрузка** (MainButton disabled + спиннер/текст «Оформляем заказ…»).
- [ ] **Тёмная тема** (основное состояние).

## Экран 4: PhoneRequestScreen — запрос телефона

**Новый экран**, отсутствующий в `pirosmani-frontend`. Показывается **перед первым заказом**,
когда `client.has_phone === false`.

### Макет

1. **Header**: только `BackButton` (возврат на предыдущий экран без отправки заказа).
2. **Центр экрана**:
   - Иконка/иллюстрация (телефон 📱 или замок 🔒).
   - Заголовок: «Для оформления заказа нужен ваш номер телефона».
   - Подзаголовок: «Он нужен для SMS-уведомлений о статусе заказа и связи с курьером».
3. **Кнопка**: «Поделиться номером» — стилизована как MainButton или отдельная кнопка в центре.
   - При тапе вызывается нативный Telegram-диалог `requestContact` (системное окно — его макетировать не нужно).
4. **Альтернатива**: кнопка «Пропустить» (серая, под основной) — возврат назад, заказ не оформляется.

### Состояния

- [ ] **Базовое** (светлая тема).
- [ ] **Тёмная тема**.

## Цветовые токены Telegram `themeParams`

Макет должен использовать CSS-переменные со следующими fallback'ами (светлая тема =
фирменный стиль Пиросмани, тёмная тема = стандартные тёмные значения Telegram):

| CSS-переменная | Telegram-ключ | Светлая (fallback) | Тёмная (fallback) |
|---|---|---|---|
| `--tg-bg-color` | `bg_color` | `#FDFBF7` | `#1A1A1A` |
| `--tg-text-color` | `text_color` | `#1A1008` | `#F5EDE0` |
| `--tg-hint-color` | `hint_color` | `#7A6A60` | `#A89580` |
| `--tg-link-color` | `link_color` | `#D36135` | `#D36135` |
| `--tg-button-color` | `button_color` | `#58111A` | `#58111A` |
| `--tg-button-text-color` | `button_text_color` | `#F5EDE0` | `#F5EDE0` |
| `--tg-secondary-bg-color` | `secondary_bg_color` | `#EDE5D8` | `#252222` |

> Значения `hint_color` и `button_text_color` сверены с фактическим кодом
> [`MenuPage.tsx:159`](../pirosmani-frontend/src/pages/MenuPage.tsx:159),
> [`CartPage.tsx:39`](../pirosmani-frontend/src/pages/CartPage.tsx:39) и
> [`CartPage.tsx:144`](../pirosmani-frontend/src/pages/CartPage.tsx:144) — в исходном
> `pirosmani-frontend` `muted` = `#7A6A60` (светлая) / `#A89580` (тёмная), а текст на
> тёмно-бордовой CTA-кнопке всегда `#F5EDE0` (не чисто белый) независимо от темы.

**Задача для макета**: провалидировать, что фирменный оранжевый `#D36135` (лого, акценты)
не «выпадает» из Telegram-темы в тёмном режиме. Если контраст недостаточен — предложить
альтернативный акцентный цвет для тёмной темы.

## Чего НЕ нужно макетировать

- **Phone-frame** (Dynamic Island, статус-бар, скругления корпуса) — в Telegram WebView этого нет, интерфейс на всю ширину.
- **BottomNav** — её нет в Mini App вообще.
- **AuthSheet** — аутентификация автоматическая через `initData`, экран входа не показывается.
- **ProfilePage, OrdersPage, PromoPage** — они форкаются 1:1 с минимальной адаптацией (только header + цвета), не требуют компоновочных изменений.
- **DishDetailSheet, VariantPickerSheet, SearchSheet** — модальные окна, переиспользуются без изменений.
- **Нативный диалог `requestContact`** — это системное окно Telegram, дизайнеру не подвластно.

## Рекомендуемый порядок работы в Figma

1. Создать фрейм 390×844 (iPhone 14 Pro).
2. Настроить color variables под 6 токенов `themeParams` из таблицы выше (светлая тема).
3. Отрисовать **MenuPage** (базовое состояние) — это точка входа, с неё начинается весь user flow.
4. Отрисовать **CartPage** (с товарами).
5. Отрисовать **CheckoutPage** (доставка, всё заполнено).
6. Отрисовать **PhoneRequestScreen**.
7. Продублировать все экраны в **тёмной теме** (переключить color variables).
8. Проверить контраст оранжевого `#D36135` в тёмной теме, при необходимости скорректировать.

## Связь с `pirosmani-frontend` (Figma Make)

Текущий [`pirosmani-frontend`](../pirosmani-frontend) — проект Figma Make
(есть [`.figma/`](../pirosmani-frontend/.figma) директория, [`AGENTS.md`](../pirosmani-frontend/AGENTS.md)
описывает его как «React + Vite + Tailwind CSS project running inside Figma Make»).

**Опционально (если макет делается в Figma Make)**:
- Сделать отдельную страницу/вариант в том же Figma-файле, что и `pirosmani-frontend` —
  тогда Figma Make сможет авто-сгенерировать React-код для Mini App,
  что сократит ручную работу на шагах 4–7 промпта DeepSeek.
- Компоненты из `pirosmani-frontend` (SafeImage, VariantPickerSheet, CardForm, AddressForm)
  переиспользовать как Master Components — менять только обёртку страницы (header/MainButton).
