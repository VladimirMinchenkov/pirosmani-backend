# Промпт для DeepSeek: визуальный React-прототип Mini App (вместо Figma-макета)

> Этот документ — **отдельный, более ранний этап** относительно
> [`telegram-mini-app-deepseek-prompt.md`](telegram-mini-app-deepseek-prompt.md).
> Здесь цель — только **визуальная проверка** компоновки из
> [`figma-mini-app-tz.md`](figma-mini-app-tz.md), без реальной интеграции с
> backend/Telegram SDK. Если прототип одобрен — переходим к полному промпту
> (реальный `initData`, реальный API, реальный `@telegram-apps/sdk`).

---

## Чем это отличается от того, что сделал бы Figma Make

| | Figma Make (реальный дизайн-инструмент) | Этот React-прототип |
|---|---|---|
| Точка старта | Пустой canvas, дизайнер расставляет элементы визуально | Копия существующего JSX из `pirosmani-frontend` (уже написанного ранее) |
| Источник цветов/отступов/шрифтов | Дизайнер выбирает заново, может улучшить иерархию | **Копирует 1:1** значения, уже захардкоженные в `pirosmani-frontend` — никакого нового дизайн-ревью не происходит |
| Редактируемость | Файл открывается в Figma, дизайнер двигает слои мышкой | Только через правку кода (JSX/CSS) |
| Состояния/варианты экрана | Figma Variants — переключаются в UI одним кликом | Нужны dev-only переключатели (кнопки в углу экрана: "тёмная тема", "корзина пуста/полна" и т.п.), которые я добавлю в код специально для проверки |
| Соответствие реальному Telegram | Не гарантирует — это просто картинка/код без реального WebView | Тоже не гарантирует — см. раздел про эмуляцию ниже |
| Что получаем в итоге | Статичный макет + сгенерированный код (нужно ещё вручную подключать API) | **Уже рабочий код** — часть этого прототипа станет частью финального `pirosmani-telegram-app` (экономит шаги 4, 5-6 полного промпта) |

**Главный практический вывод**: раз у меня нет доступа к Figma API, а исходный JSX уже
существует в `pirosmani-frontend`, результат "рисования макета в коде" и "написания
реального прототипа" — это **одна и та же работа**. Поэтому вместо двух этапов
(макет → потом код) мы сразу получаем код, который лишь позже донастраивается под
реальный API и реальный Telegram SDK.

**Чего не будет, в отличие от настоящего Figma Make**: свежего дизайн-ревью (проверки,
что иерархия/отступы/типографика оптимальны) — прототип механически следует ТЗ,
не предлагая улучшений компоновки. Если нужен именно дизайнерский взгляд —
это делает человек в Figma по ТЗ [`figma-mini-app-tz.md`](figma-mini-app-tz.md).

## Что такое «имитация Telegram» и почему она не 100% точная

Вне настоящего Telegram-клиента объект `window.Telegram.WebApp` (через который
работают `MainButton`, `BackButton`, `themeParams`) **просто не существует** —
браузер о нём не знает. Чтобы код не падал при разработке вне Telegram, есть
два уровня «имитации»:

1. **JS-мок объекта `Telegram.WebApp`** — библиотеки типа `mockTelegramEnv` из
   `@telegram-apps/sdk` подставляют фейковый объект с нужными полями
   (`initDataRaw`, `themeParams`, методы `MainButton.show()/hide()/setText()`).
   Это позволяет **коду** работать без ошибок в обычном браузере — но сам
   `MainButton` в реальности рисуется **нативно самим приложением Telegram**
   (iOS/Android/Desktop/Web — у каждого свой рендерер с чуть разными шрифтами,
   скруглениями, поведением при скролле). Мок только эмулирует API вызовов, не
   визуальный вид кнопки.

2. **Визуальная имитация кнопки в CSS** (то, что я нарисую в прототипе) — просто
   `<div>` с текстом и стилями, похожими на `MainButton` (цвет из `themeParams`,
   позиция снизу, похожая высота/скругление). Это **приближение**, не точная
   копия — реальная кнопка в Telegram Desktop выглядит немного иначе, чем в
   Telegram для iOS.

**Вывод**: ни один инструмент (ни Figma, ни мой прототип, ни любой другой браузерный
мок) не даст 100% точное превью того, как `MainButton`/`BackButton` выглядят в
реальном Telegram-клиенте. Единственный надёжный способ проверки — открыть
приложение через настоящего бота на настоящем устройстве (это и есть этап 4.14
"Fire-drill тест" из основного плана). Прототип нужен только для того, чтобы
проверить **компоновку контента** (не съедает ли контент места под кнопкой,
не наезжают ли элементы друг на друга, читаемы ли цвета в двух темах) —
не финальный пиксель-перфект самой кнопки.

## Промпт для DeepSeek (визуальный прототип)

```
Ты создаёшь ВИЗУАЛЬНЫЙ ПРОТОТИП Telegram Mini App — без реального backend API,
без реального Telegram SDK. Цель — только проверить компоновку экранов.

КОНТЕКСТ:
- ТЗ на экраны: pirosmani-backend/plans/figma-mini-app-tz.md — прочитай целиком.
- Референс для копирования JSX: ../pirosmani-frontend/src/pages/
  (MenuPage.tsx, CartPage.tsx, CheckoutPage.tsx).
- ЭТО НЕ финальная реализация. Реальный API и @telegram-apps/sdk подключаются
  позже, по отдельному промпту pirosmani-backend/plans/telegram-mini-app-deepseek-prompt.md.

ЗАДАЧА: в новом проекте pirosmani-telegram-app/ (или в поддиректории prototype/,
если проект уже существует) создать статический click-through прототип 4 экранов:
MenuPage, CartPage, CheckoutPage, PhoneRequestScreen.

ЧТО ИСПОЛЬЗОВАТЬ:
- Данные — статичные моки (несколько блюд, категорий) прямо в коде, БЕЗ похода
  к api/v1.
- Вместо window.Telegram.WebApp.MainButton — простой <div> с fixed-позицией
  внизу экрана, стилизованный под нативную кнопку (текст, цвет из CSS-переменных
  темы, высота ~50px, position: fixed, bottom: 0).
- Вместо window.Telegram.WebApp.BackButton — простая кнопка-стрелка в header.
- CSS-переменные тем — по таблице из раздела "Цветовые токены" figma-mini-app-tz.md.

ОБЯЗАТЕЛЬНО добавить dev-панель управления состояниями (плавающая панель в углу
экрана, не часть самого макета) с переключателями:
- Тема: светлая / тёмная
- Корзина: пусто / с товарами / сумма меньше минимума
- CheckoutPage: обычное состояние / ошибка / загрузка
- Экран: Menu / Cart / Checkout / PhoneRequest (быстрый переход между ними)

Это нужно, чтобы отревьюить все состояния из чек-листов figma-mini-app-tz.md
одним запуском `npm run dev`, без реального прохождения по флоу.

ПОСЛЕ ЗАВЕРШЕНИЯ:
- Сделай README.md с инструкцией "npm run dev" и списком, какие состояния
  доступны через dev-панель.
- Напиши краткое summary: какие компоненты скопированы из pirosmani-frontend
  почти без изменений, какие написаны с нуля (dev-панель, имитация MainButton/
  BackButton).

ОГРАНИЧЕНИЯ:
- Не подключай @telegram-apps/sdk и не пытайся вызывать retrieveLaunchParams() —
  в этом прототипе это не нужно.
- Не создавай реальных API-запросов к pirosmani-backend.
- TypeScript, Tailwind CSS v4 — как в pirosmani-frontend.
```

## После одобрения прототипа

1. Код header/MainButton-имитации/BackButton-имитации, компоновка страниц —
   переносится в реальный `pirosmani-telegram-app` как основа.
2. Имитация `MainButton`/`BackButton` **заменяется** на реальные вызовы
   `@telegram-apps/sdk` (шаги 4.5–4.8 основного промпта).
3. Моковые данные заменяются на реальные вызовы `api.ts` → `api/v1`.
4. Dev-панель переключения состояний — либо удаляется, либо остаётся под
   флагом `import.meta.env.DEV` для дальнейшей отладки.
